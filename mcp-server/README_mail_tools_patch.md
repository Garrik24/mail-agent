# mail_tools_patch — рабочий поиск и перемещение писем

Добавляет пять MCP-инструментов поверх существующих, ничего не переписывая.
Файлы: `mail_tools_patch.py`, `imap_utf7.py`, тесты `test_mail_tools_patch.py`.
Только стандартная библиотека, `requirements.txt` не менялся.

## Что добавлено

| Инструмент | Назначение |
|---|---|
| `list_folders` | Список папок: человекочитаемое имя + raw-имя IMAP + разделитель + флаги |
| `create_folder` | Создать папку по обычному имени, в том числе кириллицей |
| `search_mail` | Поиск: UTF-8, флаги, вложения, признак PDF, компактный вывод |
| `move_email` | Переместить одно письмо в папку |
| `move_emails` | Переместить пачку писем одной командой |

Старые инструменты (`search_emails`, `get_folders`, `get_important_emails` и
прочие) остались как были — имена не пересекаются.

## Зачем это понадобилось

`imaplib` держит `IMAP4._encoding = 'ascii'` и кодирует строковые аргументы
команды до отправки, поэтому `search_emails(query="согласование")` падал с
`'ascii' codec can't encode characters`. Здесь аргументы SEARCH уходят как
UTF-8 **bytes** с объявлением `CHARSET UTF-8`, имена папок кодируются в
modified UTF-7 (RFC 3501 §5.1.3), метаданные читаются одним `UID FETCH`
с `BODYSTRUCTURE` — отсюда настоящие флаги и вложения вместо пустых полей.

## Подключение

В `main.py`, сразу после создания объекта `mcp`:

```python
from mail_tools_patch import register_tools as register_mail_tools_patch
register_mail_tools_patch(mcp)
```

**Откат** — удалить эти две строки. Файлы модуля можно оставить, они ни на
что не влияют.

## Поле `mode` в ответе `search_mail`

Показывает, как именно отработал поиск:

- `server` — `UID SEARCH CHARSET UTF-8 …` прошёл, результат от сервера, ищет
  и по темам, и по телам писем;
- `server-nocharset` — сервер отказался от объявления кодировки, но принял
  критерии без него; результат тоже серверный;
- `client-filter` — сервер отказал совсем. Письма отобраны по датам, флагам и
  латинскому отправителю, а ключевые слова применены **к темам** на нашей
  стороне. Тела писем в этом режиме не проверяются — выдача заведомо неполная.

## Особенности поведения

- **Несколько ключевых слов** объединяются по ИЛИ префиксной цепочкой IMAP:
  `["a","b","c"]` → `OR OR SUBJECT "a" SUBJECT "b" SUBJECT "c"`.
- **`date_to` включительно** — в `BEFORE` уходит следующий день. Даты
  форматируются как `08-Jun-2026`, месяцы заданы списком, локаль не влияет.
- **`compact=True` (по умолчанию)** — одна строка на письмо:
  `18357 | 2026-06-08 09:45 | Имя <addr> | Тема [флаг, pdf]`.
  Полная выдача на сотни писем съедает контекст модели, поэтому полные
  объекты отдаются только при `compact=False`.
- **`has_attachment` и `pdf_only`** фильтруются на нашей стороне по
  `BODYSTRUCTURE` — надёжного серверного критерия для этого в IMAP нет.
  Фильтр применяется уже после отсечения по `limit`, поэтому `count` может
  быть меньше, чем видно писем в окне поиска; `total_matched` показывает,
  сколько UID вернул сам SEARCH.
- **`limit`** берёт самые свежие письма (хвост выдачи SEARCH).
- **FETCH бьётся пачками по 200 UID.**

## Перемещение писем

`move_email` / `move_emails` используют `UID MOVE`, если сервер объявил
capability `MOVE`. Если нет — `UID COPY` + `UID STORE +FLAGS (\Deleted)`,
и дальше:

- есть `UIDPLUS` → `UID EXPUNGE` только по перемещённым UID;
- нет `UIDPLUS` → оригиналы остаются помеченными к удалению, в ответе
  приходит `note`. Голый `EXPUNGE` выполняется **только** при явном
  `expunge_fallback=True`, потому что он вычистит из папки все письма,
  ранее помеченные к удалению, а не только наши.

Использованный способ возвращается в поле `method`. UID валидируются до
подключения: допускаются только цифры.

## Переменные окружения

Ничего нового не заводится. Логин ищется по очереди в `MAIL_USERNAME`,
`MAIL_LOGIN`, `MAIL_USER`, `IMAP_USER`, `IMAP_LOGIN`, `EMAIL_USER`,
`MAIL_ADDRESS`; пароль — в `MAIL_PASSWORD`, `MAIL_PASS`, `IMAP_PASSWORD`,
`IMAP_PASS`, `EMAIL_PASSWORD`; хост — `MAIL_IMAP_HOST` / `IMAP_HOST`
(по умолчанию `imap.mail.ru`), порт — `MAIL_IMAP_PORT` / `IMAP_PORT`
(по умолчанию 993). Проект использует первые в каждом списке.

## Тесты

```bash
python3 -m unittest test_mail_tools_patch -v
```

Сети и кредов не требуют — всё на синтетических ответах IMAP. Покрывают:
кодек modified UTF-7 (включая вектор из RFC 3501), разбор строк `LIST`,
`resolve_folder`, сборку критериев SEARCH, разбор `BODYSTRUCTURE` и
MIME-encoded имён вложений, парсинг FETCH с флагами и заголовками,
компактный формат, валидацию UID и все три ступени фолбэка `mode`.
