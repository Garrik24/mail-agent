# FORWARD_ALLOWLIST: Пересылка офисных файлов на доверенные адреса

## Описание

По умолчанию офисные файлы (.docx, .doc, .xlsx, .xls, .pptx, .rtf, .odt) нельзя отправлять на внешние адреса для защиты конфиденциальной информации. Однако при пересылке оригинальных вложений из входящих писем на адреса доверенных подрядчиков часто требуется отправить именно офисные файлы без изменений.

Переменная окружения `FORWARD_ALLOWLIST` позволяет указать адреса, на которые разрешена отправка офисных файлов из входящих писем.

## Настройка

Установите переменную окружения в Railway:

```
FORWARD_ALLOWLIST=info@expert-geofizika.ru,geo27@expert-geofizika.ru,vdovenko001@mail.ru,stavproektstroy@yandex.ru,ooostiz@yandex.ru
```

## Правила

1. **Разрешение**: Офисный файл можно отправить на внешний адрес ТОЛЬКО если:
   - Файл взят из входящего письма (параметр `email_attachments` в инструментах отправки)
   - **ВСЕ** получатели письма (to и cc) находятся в `FORWARD_ALLOWLIST`

2. **Блокировка**: Офисный файл блокируется на внешние адреса во всех остальных случаях:
   - Файл создан ассистентом или загружен по ссылке (base64, attachment_ids, attachment_urls)
   - Хотя бы один получатель не в списке (даже если один в списке, другой вне списка)
   - FORWARD_ALLOWLIST не задана или пустая

3. **Внутренние адреса**: Офисные файлы всегда разрешены на внутренние адреса (INTERNAL_EMAILS, MAIL_USERNAME), независимо от FORWARD_ALLOWLIST

## Логирование

При успешной пересылке офисного файла на доверенный адрес в логах Railway указывается:

```
Офисные файлы из входящего письма разрешены на доверенные адреса: uid=12345, files=Договор.docx, Смета.xlsx, recipients=partner@example.ru
```

## Новый инструмент: forward_clean

Добавлен специализированный MCP-инструмент для чистой пересылки писем:

```
forward_clean(
    email_uid: str,           # UID оригинального письма
    to: str,                  # Email получателя
    subject: str,             # Новая тема письма
    body: str,                # Новый текст (без заголовков оригинала)
    folder: str = "INBOX",    # Папка оригинала
    cc: str = "",             # Копия (опционально)
    filenames: str = "",      # JSON-список имён вложений или пусто (все кроме картинок подписи)
    read_receipt: bool = False,
    urgent: bool = False
)
```

**Особенности:**
- Не включает текст, заголовки, цитату и подпись оригинального письма
- Отправляет новое письмо от нашего ящика с вашим текстом и стандартной подписью
- Офисные файлы проверяются по тем же правилам FORWARD_ALLOWLIST
- Копия сохраняется в папку Отправленные

## Примеры использования

### send_new_email с email_attachments
```python
send_new_email(
    to="partner@example.ru",
    subject="Счёт",
    body="Счёт во вложении",
    email_attachments='[{"uid": "123", "folder": "INBOX", "filename": "Счет.docx"}]'
)
```
✓ Разрешено: файл из входящего письма, адрес в FORWARD_ALLOWLIST

### send_reply с email_attachments
```python
send_reply(
    email_uid="456",
    body="Документ вам отправляю",
    email_attachments='[{"uid": "789", "folder": "INBOX", "filename": ""}]'
)
```
Разрешено, если все получатели (из оригинального письма) в FORWARD_ALLOWLIST

### forward_clean
```python
forward_clean(
    email_uid="123",
    to="contractor@mail.ru",
    subject="Техническое задание",
    body="Пересылаю ТЗ для работы",
    filenames='["ТЗ.docx"]'
)
```
✓ Разрешено и рекомендуется вместо обычной пересылки для конфиденциальных документов
